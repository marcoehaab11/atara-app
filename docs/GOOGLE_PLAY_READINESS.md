# جاهزية «رتّب العطارة» لـ Google Play

آخر تحديث: 29 سبتمبر 2026. هذا الملف يلخص ما هو موجود في المشروع وما يلزم قبل النشر؛ لا يعني أن التطبيق جاهز لرفع إصدار عام.

## الحالة الحالية

- اكتملت مراحل التطوير 1–6 حسب `docs/GAME_SPEC.md`: اللعبة الأساسية، 1000 مستوى محضّر، اللعب والحفظ، حركة البرطمانات، المتجر والطلبات والثيمات، والمكافآت والتحدي اليومي.
- واجهة عربية افتراضيًا وإنجليزية، مع ترجمة للنصوص. الحفظ محلي ويعمل دون اتصال.
- اختبارات Node وTypeScript وESLint وبناء الويب نجحت في التحقق الأخير. تفاصيل التنفيذ والاختبار اليدوي موجودة في `docs/PHASE_6_REPORT.md`.
- يوجد غلاف Capacitor وإعدادات الويب فقط. لا يوجد مجلد Android أو ملف APK/AAB. لذلك لا توجد نسخة Android قابلة للتثبيت أو الإرسال حاليًا.
- لا توجد إعلانات أو مشتريات حقيقية أو خدمات Google Play مربوطة. أزرار هذه الميزات ما زالت مؤجلة/معطلة.
- لا يوجد رابط سياسة خصوصية، ولا نماذج Play Console، ولا بيانات متجر أو لقطات شاشة نهائية.

## المتبقي حسب مراحل المشروع

### المرحلة 7 — الإعلانات والشراء التجريبي

- بناء واجهات وهمية قابلة للتجربة للإعلانات والمشتريات وعرض Starter Pack، ثم توصيل التنفيذ الحقيقي لاحقًا حسب المواصفات.
- تطبيق شروط الإعلان: لا إعلان تلقائي أو بانر، الإعلان الاختياري لا يمنح المكافأة إلا بعد callback المكافأة، وفواصل محدودة حسب القواعد؛ موافقة UMP قبل تحميل الإعلانات وإيقاف الموسيقى أثناءها.
- يطبق المشروع الآن محاكاة الإعلانات والمشتريات في المتصفح فقط، مع تنبيه واضح بأنها تجريبية ولا تخصم أموالًا. قواعد التوقيت ومكافأة الإعلان واختبارها موثقة في `docs/PHASE_7_REPORT.md`.
- أضيفت إضافة AdMob المحددة في المواصفات وربط Native يستخدم Google rewarded/interstitial test IDs وUMP قبل طلب إعلان. ما زال فحصها على جهاز Android معطّلًا حتى إنشاء مشروع Android وإضافة AdMob App ID في المرحلة 8؛ لا تضع معرّفات إعلان إنتاجية قبل موافقة المالك على إصدار الإطلاق.

### المرحلة 8 — Android والخدمات الأصلية

- تثبيت/التحقق من Android Studio وAndroid SDK وJava على جهاز البناء، وإضافة مشروع Capacitor Android وضبط portrait وsafe areas والرجوع ولوحة المفاتيح والأيقونة وشاشة البداية وأرقام الإصدار.
- حاليًا لا يمكن إنتاج AAB لأن مشروع Android غير موجود. نسخة الإطلاق يجب أن تستهدف API 36 وفق موعد Google Play الساري في تاريخ هذا التقرير.
- اختبار الأداء والحفظ والسلوك على هاتف Android فعلي؛ قياس 24 قطعة المتوفر حتى الآن كان على سطح المكتب فقط.
- توصيل Analytics وPlay Games والحفظ السحابي والإنجازات والمراجعة والتذكير، بعد اختيار الإضافات/الجسور الأصلية المناسبة والتحقق من واجهاتها.
- إنشاء مفتاح رفع وحفظ نسخة احتياطية آمنة خارج Git. لا ترفع ملف المفتاح أو كلمات مروره أو بيانات الخدمات السرية إلى المستودع.

### المرحلة 9 — المشتريات

- إنشاء ربط RevenueCat وGoogle Play Billing للمنتجات `remove_ads` و`hints_10` و`starter_pack`، واختبار الاستعادة ومنح محتويات Starter Pack مرة واحدة.
- أزرار الشراء في المتصفح محاكاة تعليمية محلية بلا دفع؛ أزرار الشراء الأصلية ما زالت غير موصولة. لا تعتبر مكافآت المتصفح شراءً فعليًا ولا تستخدمها داخل إصدار Play.
- الأسعار لم تُحدد بعد؛ يلزم تحديدها قبل إنشاء المنتجات في Play Console. استخدم حسابات الترخيص للاختبار ولا تختبر بشراء إنتاجي.

### المرحلة 10 — صفحة المتجر والاستعداد للإطلاق

- تجهيز سياسة خصوصية عامة تطابق الخدمات التي ستُفعّل فعليًا، ثم إكمال Data safety، تصنيف المحتوى، تصريح الإعلانات، الجمهور المستهدف 13+ وملاحظات الوصول.
- إعداد اسم ووصف قصير وطويل بالعربية والإنجليزية، أيقونة 512×512، صورة مميزة 1024×500 ولقطات شاشة نهائية من إصدار الهاتف.
- تأكيد حقوق الرسومات البديلة المقدمة من المالك، وإضافة موسيقى تجارية مرخصة؛ الموجود حاليًا موسيقى تطوير مولدة برمجيًا وتُستبعد من الإنتاج.
- تجهيز مسار الاختبار المغلق ومتابعة ملاحظات المستخدمين قبل طلب إتاحة الإنتاج.

## خطوات حساب Google Play

هذه خطوات للحساب والمالك وليست تغييرات داخل الكود:

1. استكمال التحقق من هوية حساب المطور وإعداد ملف الدفعات إن كانت هناك مشتريات.
2. للحساب الشخصي الجديد: تشغيل اختبار مغلق يضم 12 مختبرًا على الأقل مدة 14 يومًا متصلة، ثم التقدم لإتاحة الإنتاج. الأفضل تجنيد 15 لتجنب النقص عند انسحاب أحدهم؛ راجع Play Console لأن أهلية الحساب هي التي تحدد الإجراء.
3. قبل الإرسال: رفع AAB موقّع، مراجعة تقارير ما قبل الإطلاق وسياسات Google، والإجابة بدقة عن كل نماذج التطبيق والإعلانات والبيانات.
4. لا تضغط على إعلاناتك بنفسك. استخدم معرفات الاختبار أثناء التطوير.

## فحوص المشروع المحلية

من PowerShell داخل مجلد المشروع:

```powershell
npm ci
npm test
npm run typecheck
npm run lint
npm run build
npm run dev -- --host
```

تثبّت الأوامر السابقة اعتماديات القفل، وتشغّل الاختبارات والتحقق والبناء، ثم تفتح خادم تجربة ويب يمكن للهاتف الوصول إليه عبر نفس شبكة Wi-Fi. نجاح بناء الويب لا ينتج AAB ولا يثبت توافق Android.

## ما ينبغي رؤيته عند التجربة

- في المتصفح: تبدأ اللعبة بالعربية، ويمكن التبديل للإنجليزية؛ جرّب حركة صب، التراجع، إعادة المرحلة، الحفظ بعد إعادة التحميل، المتجر والطلب، ثم مكافأة اليوم والتحدي اليومي.
- يجب أن تنجح `npm test` و`npm run typecheck` و`npm run lint` و`npm run build` قبل بدء المرحلة التالية.
- الهاتف عبر خادم الويب يختبر واجهة الويب فقط؛ اختبار Android والإعلانات والمشتريات الأصلية ينتظر تنفيذ المراحل 7–9.

## المصادر الرسمية والمتابعة

- متطلب API المستهدف: [Google Play target API requirements](https://developer.android.com/google/play/requirements/target-sdk)؛ من 31 أغسطس 2026 تتطلب التطبيقات الجديدة والتحديثات API 36 أو أحدث.
- الاختبار للحسابات الشخصية الجديدة: [Google Play Help — app testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)؛ يتطلب 12 مختبرًا مستمرين في الاختبار المغلق 14 يومًا قبل طلب الإنتاج للحسابات المشمولة.
- راجع المصادر وPlay Console مرة أخرى عند الإرسال لأن المواعيد والأهلية والسياسات قد تتغير.
